ARCHITECTURAL DECISION MAKING

State Management Selection Strategy

Rather than blindly enforcing a single framework, I select state architectures based on team scale, testability requirements, and feature isolation:

Enterprise / Complex

BLoC & Cubit

Strict event-to-state separation. Unidirectional data flow ideal for enterprise apps, audit trails, and decoupled unit testing.

Use case: Fintech, high-concurrency apps, multi-developer teams
Modern / Reactive

Riverpod

Compile-safe, decoupled from the Flutter widget tree. Zero BuildContext requirements for state access, with great caching and async providers.

Use case: Complex reactive feeds, asynchronous streams, multi-provider apps
Lightweight / Standard

Provider

Officially recommended standard for scoped dependency injection and straightforward reactive UI binding with minimal boilerplate.

Use case: Mid-sized applications, theme/auth state propagation
Rapid Prototyping

GetX

High-velocity micro-controllers with decoupled route management, reactive observables, and snackbar/dialog triggers without context.

Use case: Fast-turnaround MVPs, utility apps, lightweight widgets
